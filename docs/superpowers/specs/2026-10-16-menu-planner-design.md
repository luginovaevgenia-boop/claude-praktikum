# Семейный планировщик меню и покупок — спецификация

Дата: 2026-10-16

## Цель

Снять с мамы ежедневную нагрузку «что готовить». В воскресенье она быстро и
легко собирает меню на неделю (завтрак, обед, ужин на 7 дней), а приложение
само строит список покупок. Вся семья видит одно общее меню со своих телефонов.

Критерий успеха: мама собирает неделю за пару минут — одна кнопка, затем точечные
правки; список покупок получается без ручного подсчёта.

## Зафиксированные решения

- Формат: веб-приложение в браузере (телефон и компьютер), можно добавить на главный экран.
- Сценарий: кнопка «Составить неделю», затем правки (замена блюда, отключение приёма пищи).
- Блюда: готовая база простых семейных блюд (~80), мама может добавлять и править свои.
- Общий доступ: вся семья видит одно меню; облачное хранение (Firebase Firestore), вход по семейному коду.
- Приёмы пищи: завтрак, обед, ужин. Любой приём пищи на любой день можно отключить («не готовим»): для него нет блюда и продуктов в покупках.
- Ограничения по еде: нет, едим всё.
- Продукты дома: список «что дома» заполняется на каждую неделю заново; продукты из него по возможности используются в меню и вычитаются из покупок.
- Число человек в семье — настройка; количества продуктов в базе заданы на одного человека.

## Экраны

1. **Что дома** — список продуктов с галочками и поиском; шаг можно пропустить.
2. **Неделя** — сетка 7 дней × 3 приёма. Кнопка «Составить неделю»; клик по блюду — замена («другое случайное» или выбор из списка); переключатель «не готовим» у каждой ячейки.
3. **Покупки** — список по отделам магазина, пересчитан на число человек, без домашних продуктов; пункты вычёркиваются.
4. **Сегодня** — завтрак, обед, ужин на сегодня.
5. **Настройки** — число человек, семейный код, добавление и правка своих блюд.

## Структура файлов

Папка `menu/` в репозитории, сборка не нужна:

- `menu/index.html`, `menu/styles.css` — оболочка и стили.
- `menu/app.js` — интерфейс и работа с хранилищем.
- `menu/dishes.js` — база блюд.
- `menu/logic.js` — чистые функции без обращений к браузеру и облаку.
- `menu/storage.js` — слой хранения: Firebase Firestore или локальный режим.
- `menu/tests/` — тесты логики.

## База блюд

У каждого блюда: название; приём пищи (завтрак / обед / ужин; допускается «обед или ужин»);
продукты (название, количество на одного человека, единица: г, шт, мл; отдел магазина).
Свои блюда мамы хранятся в облаке и объединяются с базой.

## Логика

- `generateWeek(dishes, pantry, currentMenu)` (отключённые приёмы берутся из `currentMenu`): заполняет все активные ячейки,
  не ставит одно блюдо два раза подряд и ограничивает повторы за неделю, отдаёт предпочтение
  блюдам, использующим продукты из «что дома».
- `buildShoppingList(menu, pantry, people)`: суммирует продукты всех блюд меню на число человек,
  вычитает домашние запасы, группирует по отделам; отключённые ячейки не учитываются.

Обе функции чистые и покрываются тестами.

## Данные в облаке

Один документ на семью, ключ — семейный код. Содержит: число человек, список «что дома»,
меню недели (день × приём → блюдо или «не готовим»), отметки «куплено», свои блюда.
Изменения синхронизируются на всех устройствах в реальном времени.

## Ошибки и офлайн

- Без сети приложение работает с локальной копией и синхронизируется при появлении сети.
- Без настроенного Firebase запускается в локальном режиме (данные в браузере), чтобы приложение можно было посмотреть сразу; облако подключается позже вставкой ключей в конфиг.
- Неверный семейный код — понятное сообщение, повторный ввод.

## Безопасность

Доступ только по семейному коду; правила Firestore ограничивают чтение и запись документом своей семьи.
Личных данных не хранится — только меню и продукты.

## Вне первой версии

Калории и БЖУ, цены, пошаговые рецепты, фото блюд, несколько семей в одном аккаунте.

## Тестирование

Юнит-тесты `generateWeek` (покрытие всех активных ячеек, отсутствие подряд идущих повторов,
уважение отключённых приёмов, предпочтение домашних продуктов) и `buildShoppingList`
(суммирование, масштабирование на число человек, вычитание запасов, группировка по отделам,
игнорирование отключённых ячеек). Интерфейс проверяется вручную в браузере.
